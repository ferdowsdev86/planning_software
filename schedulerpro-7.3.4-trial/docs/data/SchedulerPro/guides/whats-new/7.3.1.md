# What's new in Scheduler Pro v7.3.1

## Early start/end date fields caching

The release enables caching for early start/end date fields.
The fields will cache their calculated values and use them between the Engine transactions (when the Engine is
about to recalculate or recalculating data).
The reason for caching is that calculating the fields is expensive and might cause lags on large datasets.

The change should not affect your application but if it does you can revert it this way:

```javascript
// disable caching for early start/end date fields
EventModel.$entity.allFields.get("earlyStartDate").cacheValue = false;
EventModel.$entity.allFields.get("earlyEndDate").cacheValue = false;
```

If your application extends `EventModel` then above code should use your class instead.
